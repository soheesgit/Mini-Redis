# 미니 Redis 공부 지도

**총 7.5시간.** 깊게 볼 곳은 3곳(★★★)이고, 이 3곳에 4.5시간을 씁니다. 나머지는 "무엇을 왜 하는지"만 잡고 넘어갑니다.

DBMS 공부와 겹치는 개념이 많습니다(아래 연결표). 여기서 한 번 제대로 이해하면 DBMS 쪽 시간이 줄어듭니다.

---

## 탑다운 순서

```
Level 0  요청 하나를 끝까지 따라가기 (30분)          ← 전체 지도
   │
Level 1  깊게 3곳 (각 1.5시간)
   ├─ ① executor 단일 스레드 ── "동시성이 없는 구조"  (04)
   ├─ ② AOF: 응답 전 기록 + 멱등 + 복구               (03)
   └─ ③ 해시 테이블: 점진적 리해싱 + 커서             (01)
   │
Level 2  "왜 있는지"만 (각 30분~1시간)
   └─ TTL(02) · LRU(05) · 압축·RDB(06) · 캐시·성능(07)
```

**깊게 볼 곳을 이 3곳으로 고른 이유**

| 기준 | ① executor | ② AOF | ③ 리해싱 |
|---|---|---|---|
| 다른 기능이 이 위에 서 있나 | 모든 데이터 접근 | 재시작·압축·RDB | 커서·만료 샘플·KEYS |
| 질문이 몰리는 곳인가 | "싱글 스레드인데 동시성?" | "꺼지면 어떻게 돼?" | "리사이즈하면 멈추지 않아?" |
| DBMS와 겹치나 | 트랜잭션 직렬화 | WAL, 복구 | 해시 인덱스 |

**얕게 가도 되는 곳**: SipHash 라운드 내부, HTTP 경로 파싱 세부, JSON 문자열 만들기, 벤치마크 코드, 파일 형식의 바이트 배치.

## Level 0: 요청 하나 따라가기 (30분)

`PUT /keys/a?ttl=10` (본문 "1")이 들어왔을 때:

```
클라이언트
  │ HTTP
  ▼
가상 스레드 (요청마다 1개)        HttpApi.java       Origin·인증·크기·키 검사
  │ ["SET","a","1","EX","10"] + 빈 future
  ▼
명령 큐 (1024칸)                   Engine.java
  ▼
executor 스레드 (1개뿐)            Engine.processBatch
  │ store.execute()               Store.java         해시 테이블에 저장, TTL 등록
  │ AOF 레코드 "SET a 1 PXAT <시각>"
  │ write 1번 (OS에 넘김)         Persistence.append
  │ future 완료
  ▼
가상 스레드가 깨어나 200 응답
          (1초마다 다른 스레드가 fsync → 디스크)
```

이 그림의 화살표 하나하나가 01~07 파일의 주제입니다.

## DBMS와 연결표 (같은 개념, 다른 이름)

| 미니 Redis | DBMS | 공통 핵심 |
|---|---|---|
| AOF, 응답 전에 write | WAL (Write-Ahead Log) | 데이터보다 로그를 먼저 남긴다 |
| 배치 write 1번 | group commit | 여러 커밋을 시스템 콜 한 번으로 |
| fsync 1초마다 | `innodb_flush_log_at_trx_commit=2` 같은 설정 | 내구성과 속도의 교환 |
| 재시작 시 AOF 재실행 | redo 복구 | 로그를 다시 적용해 상태를 만든다 |
| AOF 압축(base + incr) | checkpoint | 로그가 무한히 커지지 않게 |
| 멱등 레코드 | 물리 로그 / 멱등 redo | 두 번 적용해도 결과가 같아야 한다 |
| executor 1개 | serializable 실행 | 겹치지 않게 하나씩 → 경쟁 없음 |
| LRU 제거 | 버퍼 풀 교체 정책 | 오래 안 쓴 것부터 내보낸다 |
| 해시 테이블 | 해시 인덱스 | 등호 조회 O(1), 범위 조회는 못 함 |

## 실행

```bash
./run.sh
```

```bash
mvn test
```

JDK 25.0.5와 Maven 3.9.16은 `~/tools`에 설치되어 있습니다. 터미널을 새로 열 때마다 아래를 먼저 실행해야 `java`와 `mvn`이 이 버전을 가리킵니다. 서버를 띄우기 전에는 `mvn package`로 `target/classes`를 만들어 두세요.

```bash
export JAVA_HOME=~/tools/jdk-25.0.5+8/Contents/Home PATH=~/tools/jdk-25.0.5+8/Contents/Home/bin:~/tools/apache-maven-3.9.16/bin:$PATH
```
