# Mini DBMS 구현 계획

Phase 1의 SQL 처리기 구현과 검증을 마쳤습니다.

## Phase 1 · SQL 처리기

- [x] Java CLI 진입점에서 UTF-8 SQL 파일을 읽고, 잘못된 인자와 파일 오류를 처리한다.
- [x] 어휘 분석기와 파서를 구현한다. `INSERT INTO … (열 목록) VALUES (…)`, `SELECT 열 목록 | * FROM … [WHERE 열 = 값]`을 지원한다. 문자열의 작은따옴표는 `''`로 이스케이프하며, 문자열 안의 세미콜론을 보존한다.
- [x] 코드로 정의한 카탈로그에서 기존 테이블의 스키마를 읽는다. 첫 예제 테이블은 `users(id BIGINT, name TEXT, email TEXT)`로 두고 `INSERT`에서 테이블별 `id`를 자동 부여한다. `CREATE TABLE`은 범위 밖이다.
- [x] `INSERT`는 테이블 파일 끝에 레코드를 추가하고, `SELECT`는 필요한 행을 읽어 필터링과 열 선택을 적용한다. CLI는 SQL 파일의 순서대로 문장을 실행하고 조회 결과를 표준 출력에 표시한다.
- [x] 파서 단위 테스트에서 공백, 여러 문장, 한글, 이스케이프, 잘못된 구문을 검사한다. CLI 기능 테스트에서 임시 저장 디렉터리에 삽입한 뒤 별도 프로세스로 조회하고, 빈 테이블과 잘못된 테이블·열·값도 검증한다.

테이블 파일의 각 레코드는 4바이트 본문 길이, 8바이트 ID, 각 텍스트 열의 4바이트 길이와 UTF-8 바이트로 구성한다. 정수는 빅엔디언이며 레코드 본문은 1 MiB까지 저장한다. 레코드의 시작 바이트 위치로 해당 행을 직접 읽을 수 있는 형식이다. 실행기가 시작 후 처음 삽입할 때 파일을 순회해 다음 ID를 계산하고, 이후 같은 실행에서는 마지막으로 저장한 ID를 사용한다. 불완전한 레코드는 파일 위치를 포함한 오류로 보고한다.

## Phase 2 · B+ 트리 인덱스

- [ ] 리프 노드에 `id → 파일 위치`를 저장하고, 내부 노드에서 분리 키로 탐색 경로를 선택한다. 리프와 내부 노드의 분할, 루트 분할, 리프 연결을 구현한다.
- [ ] DB를 열 때 테이블 파일을 한 번 순회해 인덱스를 재구축한다. 삽입 시 파일 쓰기를 마친 뒤 인덱스에 위치를 추가한다. `WHERE id = 값`은 인덱스를 사용하고, 다른 열의 동등 조건은 파일을 순차 탐색한다. CLI와 SQL 문법은 Phase 1의 것을 재사용한다.
- [ ] 작은 노드 용량으로 여러 단계의 분할을 유도해 순서대로 넣은 키와 뒤섞인 키를 검증한다. 빈 트리, 없는 키, 중복 키 처리, 리프 순서도 확인한다. 엔진 통합 테스트에서 인덱스 경로와 선형 경로가 같은 행을 반환하는지 확인한다.
- [ ] 최소 1,000,000건을 SQL 처리기로 삽입해 저장하고 전체 행 수를 검증한다. 고유 `email`과 대응 `id`로 같은 행을 찾는 질의를 실행한다. 두 경로를 워밍업한 뒤 여러 대상에 대해 반복 측정한다. 초기 삽입과 인덱스 재구축 시간을 조회 시간과 분리하고, 실행 환경·측정 횟수·중앙값·p95를 기록한다.

## Phase 3 · HTTP API 서버

- [ ] JDK HTTP 서버의 `POST /query`가 UTF-8 SQL 요청 본문을 받아 기존 SQL 처리기를 호출하게 한다. CLI는 표준 출력용, API는 JSON 응답용으로 공통 실행 결과를 변환한다. 입력 오류와 저장소 오류를 HTTP 상태로 구분한다.
- [ ] 고정 크기 스레드 풀에서 요청을 처리한다. 테이블마다 읽기·쓰기 잠금을 두어 조회를 병렬 실행하고, 파일 추가와 ID 발급 및 인덱스 갱신은 같은 쓰기 잠금으로 보호한다.
- [ ] 서버를 실제로 띄워 외부 HTTP 클라이언트에서 삽입과 조회를 검증한다. 여러 삽입과 조회를 동시에 요청하고 ID 중복, 누락된 행, 파일과 인덱스의 불일치를 확인한다. 재시작 후에도 저장된 행을 조회하는지 확인한다.

CLI와 서버는 각각 단일 프로세스가 데이터 디렉터리를 소유하는 방식으로 시작한다. 동시성 검증은 서버 프로세스 내부의 여러 요청을 대상으로 한다.

## 구현 후 설명할 항목

- SQL 토큰이 문장 구조로 변환되고 파일 쓰기나 조회로 이어지는 과정
- B+ 트리의 분할이 루트까지 전파되는 경우와 ID가 파일 위치로 연결되는 과정
- 파일과 메모리 인덱스를 함께 갱신할 때 쓰기 잠금이 필요한 구간
- 추가 구현 후보로 `EXPLAIN SELECT`를 검토한다. 조회가 인덱스를 사용했는지, 몇 건을 읽었는지 CLI와 API에서 확인하는 기능이다.
